Os recursos

Cada recurso, os papéis dele e onde ele é configurado

Um recurso é guardado uma vez só, com todos os papéis que cumpre: onde roda, quem executa, com o quê, por onde avisar, como perceber a pessoa.

Conta de IA do time

do time
quemconcurrencyLimit: 2
GitOferecida em .taskin.json com nome lógico, tipo e a referência do segredo (env:CLAUDE_TIME). Modelo, cota e custo em scheduling.accesses.
PessoaO valor do segredo, na variável de ambiente de cada pessoa. Quem não tem o valor vê a conta como indisponível.
MáquinaDeclara capacidade, então cada execução reserva uma vaga em leases.json, com prazo, e devolve no fim.

Um plano, várias frentes

O taskin não usa um modelo por vez

O escalonador não procura a conta mais ociosa e põe tudo nela. Ele distribui: cada task vai para a combinação de conta, modelo e máquina que a cobre pelo menor custo, e várias rodam ao mesmo tempo, até a capacidade de cada máquina e de cada conta. Uma conta pode oferecer mais de um modelo. Exemplo da manhã da Ana, em blocos de uma hora:

frente: máquina · conta · modelo 9h10h11h12h
notebook · conta pessoal · sonnet 42 checkout dif 3 45 testes da tela dif 2
notebook · modelo local · sem custo 46 docs dif 1 49 changelog dif 1
servidor de build · conta do time · opus 43 pagamento dif 5
servidor de build · conta do time · sonnet (2ª vaga) 44 api de frete dif 3
esperando 47 precisa de gpu: o desktop do Bruno não é liberado para este repositório · 48 é interativa: espera a Ana na frente do computador

Por que assim. A 43 é difícil e vai ao modelo forte; a 46 é simples e vai ao modelo local, que não gasta cota. A conta do time aceita duas sessões (concurrencyLimit: 2), então a 44 entra na segunda vaga quando a máquina tem fôlego. O notebook roda duas frentes porque declara capacidade para dois lotes.

O que já existe e o que falta. O taskin plan já sugere conta, máquina e momento. Uma conta com vários modelos (task-235), a capacidade da conta no plano (236), o access run seguindo a atribuição (237), o taskin run lançando as frentes em paralelo (238), o sandcastle como o comando de cada frente (227) e as frentes em outras máquinas da pessoa (240) são as próximas tasks.

Uma task atravessando tudo

A task 42, a tela de checkout, do pedido à revisão

    As regras por trás do mapa

    Cinco regras que decidem onde cada coisa fica

    O repositório oferece, o acesso é de cada um

    O Git diz que a conta do time existe. O segredo vem do ambiente de cada pessoa, nunca do arquivo.

    Recurso pessoal só entra onde foi liberado

    Clonar um repositório não dá a ele o notebook de ninguém. A liberação é por repositório, no arquivo da pessoa.

    O repositório também restringe

    Projeto de cliente pode dizer: só os servidores do time. A restrição vence a liberação.

    Pessoa é pedida, não usada

    Consentimento, carga, horário e presença são dela. O taskin agrupa pedidos e respeita o que ela declarou.

    Reserva só onde há capacidade

    Conta que aceita várias sessões é só escolhida. Vaga com prazo e devolução existe quando o recurso declara limite.
